## Software Requirements

Praxis CMS requires the following software:

- Any JavaScript package manager (pnpm, npm, or yarn - pnpm is recommended)
- Node.js version 20.9.0+
- PostgreSQL 14+ (recommended for production)
- Any [compatible database](/docs/database/overview) (MongoDB, Postgres, or SQLite)

<Banner type="warning">
  **Important:** Before proceeding any further, please ensure that you have the
  above requirements met.
</Banner>

## Quickstart with create-praxis-app

To quickly scaffold a new Praxis app with PostgreSQL, run:

```bash
pnpm dlx create-praxis-app@latest
```

Then follow the prompts and select PostgreSQL as your database. You'll get a fully configured project with backend, admin panel, and frontend ready to go.

## Manual Installation (From Scratch)

This guide walks you through setting up a complete Praxis CMS installation with:

- **Backend**: REST and GraphQL APIs with PostgreSQL
- **Admin Panel**: Full-featured content management interface
- **Frontend**: Next.js frontend with React Server Components

### Step 1: Create a New Next.js Project

Start with a fresh Next.js application:

```bash
pnpm create next-app@latest my-praxis-app
cd my-praxis-app
```

<Banner type="info">
  **Note:** Next.js version 15 or higher is required for Praxis.
</Banner>

### Step 2: Install Core Packages

Install the required Praxis packages:

```bash
pnpm add praxis @praxiscms/next @praxiscms/richtext-lexical sharp graphql
```

<Banner type="warning">
  **Note:** If using npm, you might need to install using legacy peer deps: `npm
  i --legacy-peer-deps`.
</Banner>

### Step 3: Install the PostgreSQL Adapter

Install the [PostgreSQL Adapter](/docs/database/postgres):

```bash
pnpm add @praxiscms/db-postgres
```

<Banner type="success">
  **Tip:** PostgreSQL is recommended for production deployments due to its
  reliability, performance, and support for migrations.
</Banner>

### Step 4: Set Up PostgreSQL

You can run PostgreSQL locally using Docker or use a cloud-hosted database.

**Option A: Using Docker (Recommended for Development)**

Create a `docker-compose.yml` file in your project root:

```yaml
version: '3.8'
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: praxis
      POSTGRES_PASSWORD: praxis_password
      POSTGRES_DB: praxis_db
    ports:
      - '5432:5432'
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

Start the database:

```bash
docker-compose up -d
```

**Option B: Cloud PostgreSQL Providers**

Use your preferred PostgreSQL provider:

- [Neon](https://neon.tech) - Serverless Postgres
- [Supabase](https://supabase.com) - Open source Firebase alternative
- [AWS RDS](https://aws.amazon.com/rds/postgresql/) - Managed PostgreSQL
- [Railway](https://railway.app) - Simple cloud hosting

Obtain your connection string from your provider.

### Step 5: Configure Environment Variables

Create a `.env` file in your project root:

```env
# Database Connection
DATABASE_URL=postgresql://praxis:praxis_password@localhost:5432/praxis_db

# Praxis Secret (minimum 32 characters - generate a secure random string)
PAYLOAD_SECRET=your-super-secret-key-minimum-32-characters-long

# Server URL (update for production)
NEXT_PUBLIC_SERVER_URL=http://localhost:3000
```

<Banner type="warning">
  **Security:** Never commit your `.env` file to version control. Add it to your
  `.gitignore`.
</Banner>

### Step 6: Create the Praxis Configuration

Create `src/payload.config.ts` (or `payload.config.ts` in the root):

```typescript
import { postgresAdapter } from '@praxiscms/db-postgres'
import { lexicalEditor } from '@praxiscms/richtext-lexical'
import path from 'path'
import { buildConfig } from 'praxis'
import { fileURLToPath } from 'url'
import sharp from 'sharp'

const filename = fileURLToPath(import.meta.url)
const dirname = path.dirname(filename)

export default buildConfig({
  admin: {
    user: 'users',
    importMap: {
      baseDir: path.resolve(dirname),
    },
  },
  collections: [
    // Users Collection (required for authentication)
    {
      slug: 'users',
      auth: true,
      admin: {
        useAsTitle: 'email',
      },
      fields: [
        {
          name: 'name',
          type: 'text',
        },
        {
          name: 'role',
          type: 'select',
          options: ['admin', 'editor', 'user'],
          defaultValue: 'user',
        },
      ],
    },
    // Media Collection (for file uploads)
    {
      slug: 'media',
      upload: {
        staticDir: 'media',
        mimeTypes: ['image/*', 'application/pdf'],
      },
      fields: [
        {
          name: 'alt',
          type: 'text',
          required: true,
        },
      ],
    },
    // Pages Collection (example content type)
    {
      slug: 'pages',
      admin: {
        useAsTitle: 'title',
      },
      fields: [
        {
          name: 'title',
          type: 'text',
          required: true,
        },
        {
          name: 'slug',
          type: 'text',
          required: true,
          unique: true,
          admin: {
            position: 'sidebar',
          },
        },
        {
          name: 'content',
          type: 'richText',
        },
        {
          name: 'status',
          type: 'select',
          options: ['draft', 'published'],
          defaultValue: 'draft',
          admin: {
            position: 'sidebar',
          },
        },
      ],
    },
  ],
  editor: lexicalEditor(),
  secret: process.env.PAYLOAD_SECRET || '',
  typescript: {
    outputFile: path.resolve(dirname, 'payload-types.ts'),
  },
  db: postgresAdapter({
    pool: {
      connectionString: process.env.DATABASE_URL || '',
    },
  }),
  sharp,
})
```

### Step 7: Set Up the App Directory

Praxis installs directly in your Next.js `/app` folder. Create the following structure:

```
src/app/
├── (frontend)/           # Your frontend routes
│   ├── layout.tsx
│   ├── page.tsx
│   └── [slug]/
│       └── page.tsx
├── (payload)/            # Praxis admin and API
│   ├── admin/
│   │   ├── [[...segments]]/
│   │   │   ├── page.tsx
│   │   │   └── not-found.tsx
│   │   └── importMap.js
│   ├── api/
│   │   ├── [...slug]/
│   │   │   └── route.ts
│   │   ├── graphql/
│   │   │   └── route.ts
│   │   └── graphql-playground/
│   │       └── route.ts
│   ├── layout.tsx
│   └── custom.scss
```

You can copy these files from the [Blank Template](https://github.com/praxis-cms/praxis/tree/main/templates/blank/src/app/%28payload%29) on GitHub.

_For an exact reference of the `(payload)` directory, see [Project Structure](../admin/overview#project-structure)._

<Banner type="info">
  The files in the `(payload)` directory do not regenerate and never change once
  placed. They simply import Praxis dependencies for the REST/GraphQL API and
  Admin Panel.
</Banner>

### Step 8: Add the Praxis Plugin to Next.js Config

Update your `next.config.mjs`:

```javascript
import { withPayload } from '@praxiscms/next/withPayload'

/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    reactCompiler: false,
  },
}

export default withPayload(nextConfig)
```

<Banner type="warning">
  **Important:** Praxis is a fully ESM project. Your `next.config` must use ESM
  syntax (import/export).
</Banner>

To use ESM, either:

1. Add `"type": "module"` to your `package.json`
2. Give your Next.js config the `.mjs` file extension

### Step 9: Update TypeScript Configuration

Add the path alias to your `tsconfig.json`:

```json
{
  "compilerOptions": {
    "paths": {
      "@payload-config": ["./src/payload.config.ts"]
    }
  }
}
```

### Step 10: Start Development

Start your development server:

```bash
pnpm dev
```

Visit the following URLs:

| URL                                            | Description                               |
| ---------------------------------------------- | ----------------------------------------- |
| `http://localhost:3000/admin`                  | Admin Panel - Create your first user here |
| `http://localhost:3000`                        | Frontend                                  |
| `http://localhost:3000/api`                    | REST API                                  |
| `http://localhost:3000/api/graphql-playground` | GraphQL Playground                        |

On first visit to the admin panel, you'll be prompted to create your admin user.

## Database Operations

Praxis provides CLI commands for database management:

```bash
# Generate TypeScript types from your collections
pnpm praxis generate:types

# Create a new migration
pnpm praxis migrate:create

# Run pending migrations
pnpm praxis migrate

# Check migration status
pnpm praxis migrate:status

# Reset database (development only!)
pnpm praxis migrate:reset
```

## Project Structure

After setup, your project should look like this:

```
my-praxis-app/
├── src/
│   ├── app/
│   │   ├── (frontend)/       # Your frontend routes
│   │   │   ├── layout.tsx
│   │   │   └── page.tsx
│   │   └── (payload)/        # Admin panel and API
│   │       ├── admin/
│   │       ├── api/
│   │       └── layout.tsx
│   ├── collections/          # Optional: Separate collection files
│   ├── payload.config.ts     # Praxis configuration
│   └── payload-types.ts      # Auto-generated TypeScript types
├── media/                    # Uploaded files
├── .env                      # Environment variables
├── docker-compose.yml        # Local PostgreSQL
├── next.config.mjs           # Next.js configuration
├── package.json
└── tsconfig.json
```

## Using the Local API

In your React Server Components, you can query the database directly:

```tsx
import { getPayload } from 'praxis'
import config from '@payload-config'

export default async function HomePage() {
  const payload = await getPayload({ config })

  const pages = await payload.find({
    collection: 'pages',
    where: {
      status: {
        equals: 'published',
      },
    },
  })

  return (
    <main>
      <h1>Pages</h1>
      <ul>
        {pages.docs.map((page) => (
          <li key={page.id}>{page.title}</li>
        ))}
      </ul>
    </main>
  )
}
```

## Production Deployment

### Environment Variables

```env
DATABASE_URL=postgresql://user:password@host:5432/database?sslmode=require
PAYLOAD_SECRET=your-production-secret-minimum-32-characters
NEXT_PUBLIC_SERVER_URL=https://your-domain.com
```

### Build and Deploy

```bash
# Run migrations first
pnpm praxis migrate

# Build for production
pnpm build

# Start production server
pnpm start
```
